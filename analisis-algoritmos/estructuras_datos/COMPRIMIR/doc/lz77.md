# LZ77 — Lempel-Ziv 1977

> Algoritmo de compresión **universal sin pérdida** basado en ventana deslizante.
> Propuesto por **Abraham Lempel** y **Jacob Ziv** en 1977.
> Base de: gzip, zlib, PNG, ZIP, DEFLATE, zstd, Snappy.

---

## ¿Qué problema resuelve?

El texto natural (y el código fuente) está lleno de **palabras y frases que
se repiten**, pero no necesariamente de forma consecutiva:

```
"el algoritmo de compresion es un algoritmo de busqueda"
                                   └── ya apareció "algoritmo de" ──┘
```

RLE no puede aprovechar esto (no son bytes consecutivos iguales).
Huffman tampoco, ya que trabaja símbolo a símbolo.

**LZ77 detecta estas repeticiones a distancia y las reemplaza por
referencias al texto anterior.**

---

## La Ventana Deslizante

El corazón de LZ77 es una **ventana de dos partes** que avanza por el texto:

```
┌────────────────────────────┬─────────────────────┐
│     VENTANA (historial)    │  LOOKAHEAD (buffer)  │
│  últimos W bytes procesados│  próximos L bytes    │
└────────────────────────────┴─────────────────────┘
                              ↑ posición actual

W = WINDOW_SIZE   (en este proyecto: 4096 bytes)
L = LOOKAHEAD_MAX (en este proyecto: 255 bytes)
```

Para cada posición, el algoritmo busca la **cadena más larga** del
lookahead que también exista en la ventana (historial).

---

## El Token LZ77

La salida de LZ77 es una secuencia de **tokens**. Cada token es:

```c
typedef struct {
    uint16_t dist;       /* distancia al inicio del match (0 = no hay match) */
    uint8_t  length;     /* longitud del match                               */
    uint8_t  next_byte;  /* byte siguiente al match (o literal si dist=0)    */
} LZ77Token;             /* total: 4 bytes por token                         */
```

### Tipos de token

```
Token LITERAL (sin match):
  dist   = 0
  length = 0
  next   = byte a emitir directamente

Token REFERENCIA (con match):
  dist   = distancia hacia atrás en la ventana
  length = longitud del match encontrado
  next   = byte que viene después del match
```

## Ejemplo Paso a Paso

```
Texto entrada: "abcabcabc"

Paso 1: pos=0, lookahead="abcabcabc"
  Ventana: [] (vacía)
  No hay match posible → LITERAL 'a'
  Token: (0, 0, 'a')   ventana ahora: [a]

Paso 2: pos=1, lookahead="bcabcabc"
  No match → LITERAL 'b'
  Token: (0, 0, 'b')   ventana: [ab]

Paso 3: pos=2, lookahead="cabcabc"
  No match → LITERAL 'c'
  Token: (0, 0, 'c')   ventana: [abc]

Paso 4: pos=3, lookahead="abcabc"
  Ventana: [abc]
  Match: "abc" aparece en la ventana a distancia 3, longitud 3 ✓
  Token: (3, 3, 'a')  → "retrocede 3, copia 3 bytes, luego 'a'"
  Avanza 3+1 = 4 posiciones

Paso 5: pos=7, lookahead="bc"
  Match: "bc" dist=2, len=2
  Token: (2, 2, '\0')

Resultado: 5 tokens × 4 bytes = 20 bytes
Original : 9 bytes
(En este caso LZ77 no mejora — el texto es muy corto)

Con "abcabcabc" repetido 100 veces (900 bytes):
  Tokens ≈ 4 + 99×4 = 400 bytes → ~56% ahorro
```

## Algoritmo de Compresión

```
Pseudocódigo:
─────────────────────────────────────────────────────────────────
pos ← 0

MIENTRAS pos < tamaño_entrada:

    # Buscar el match más largo en la ventana
    win_start ← max(0, pos − WINDOW_SIZE)
    mejor_dist ← 0
    mejor_len  ← 0

    PARA i DESDE win_start HASTA pos−1:
        len ← 0
        MIENTRAS entrada[i+len] == entrada[pos+len]
              Y len < LOOKAHEAD_MAX:
            len++
        SI len > mejor_len:
            mejor_len  ← len
            mejor_dist ← pos − i

    # Emitir token
    SI mejor_len >= MIN_MATCH (3):
        emitir (mejor_dist, mejor_len, entrada[pos+mejor_len])
        pos ← pos + mejor_len + 1
    SINO:
        emitir (0, 0, entrada[pos])   ← literal
        pos ← pos + 1
─────────────────────────────────────────────────────────────────
```

### Búsqueda de Match: el cuello de botella

La implementación **ingenua** busca en toda la ventana para cada posición:

```
Complejidad: O(n × W × L)
  n = tamaño del archivo
  W = tamaño de la ventana (4096)
  L = longitud máxima de match (255)
```

**Implementaciones optimizadas** usan hash tables o árboles de sufijos
para llegar a O(n log n) — así funciona zlib/gzip internamente.

## Algoritmo de Descompresión

```
Pseudocódigo:
─────────────────────────────────────────────────────────────────
PARA CADA token (dist, len, next) EN stream_comprimido:

    SI dist > 0  (es una referencia):
        src ← posición_actual − dist
        COPIAR len bytes desde salida[src] a salida[pos]
        pos ← pos + len

    emitir 'next'    ← siempre se emite el byte literal
    pos ← pos + 1
─────────────────────────────────────────────────────────────────
```

> **Importante:** la copia puede solaparse con la fuente (overlap copy).
> Esto es intencional y permite codificar repeticiones largas con ventanas cortas.
> Ejemplo: `(1, 100, x)` desde `[A]` produce `[AAAA...AAA]` (100 A's).

---

## Complejidad

| Operación        | Tiempo     | Espacio  |
| ----------------- | ---------- | -------- |
| Comprimir (naive) | O(n × W)  | O(W + L) |
| Comprimir (hash)  | O(n log n) | O(W)     |
| Descomprimir      | O(n)       | O(n)     |

## Parámetros Configurables (src/lz.h)

```c
#define LZ_WINDOW_SIZE   4096   /* historial de búsqueda */
#define LZ_LOOKAHEAD_MAX  255   /* longitud máx de match */
#define LZ_MIN_MATCH        3   /* mínimo para usar ref  */
```

**Trade-off clave:** ventana más grande → mejor compresión, pero más lento.

```
WINDOW_SIZE = 256   → compresión rápida, ratio moderado
WINDOW_SIZE = 4096  → buena compresión, más lento (este proyecto)
WINDOW_SIZE = 32768 → máximo (gzip), ratio excelente, más memoria
```

## Cuándo Funciona Bien y Cuándo No

| Tipo de archivo               | Resultado                                  |
| ----------------------------- | ------------------------------------------ |
| Código fuente C/Python       | ✅ 50–70% ahorro (keywords repetidas)     |
| Texto con frases repetidas    | ✅ 40–60% ahorro                          |
| ADN (patrones repetidos)      | ✅ 60–80% ahorro                          |
| Imágenes JPEG ya comprimidas | ❌ Sin mejora                              |
| Datos aleatorios              | ❌ Aumenta el tamaño (overhead de tokens) |

## La Familia LZ — Evolución Histórica

| Algoritmo         | Año | Descripción                                      |
| ----------------- | ---- | ------------------------------------------------- |
| **LZ77**    | 1977 | Ventana deslizante (este proyecto)                |
| **LZ78**    | 1978 | Diccionario dinámico sin ventana                 |
| **LZW**     | 1984 | LZ78 con diccionario preinicializado (GIF, TIFF)  |
| **LZSS**    | 1982 | LZ77 mejorado con bit de control (literal vs ref) |
| **DEFLATE** | 1996 | LZSS + Huffman (ZIP, PNG, gzip)                   |
| **LZ4**     | 2011 | LZ77 ultra rápido para memoria RAM               |
| **zstd**    | 2016 | LZ77 + FSE (Facebook/Meta, muy rápido)           |

> **DEFLATE** (usado en ZIP y PNG) es exactamente **LZ77 + Huffman**:
> primero LZ77 reduce referencias, luego Huffman comprime los tokens.
> El programa puede simular esto ejecutando LZ77 y Huffman en cadena.

```
El archivo samples/comprimidos/out_lz77.bin contiene:
  una secuencia de LZ77Token structs de 4 bytes cada uno:

  Bytes 0-1: dist     (uint16_t, little-endian)
  Byte  2:   length   (uint8_t)
  Byte  3:   next_byte(uint8_t)

Tamaño total = número_de_tokens × 4 bytes
```

## Código Clave (src/lz.c)

```c
/* Buscar el match más largo en la ventana */
static void find_best_match(const uint8_t *buf, long pos, long size,
                             uint16_t *out_dist, uint8_t *out_len) {
    long win_start = (pos > LZ_WINDOW_SIZE) ? pos - LZ_WINDOW_SIZE : 0;
    long best_len  = 0, best_dist = 0;

    for (long i = win_start; i < pos; i++) {
        long match_len = 0;
        while (match_len < LZ_LOOKAHEAD_MAX
               && pos + match_len < size
               && buf[i + match_len] == buf[pos + match_len])
            match_len++;

        if (match_len > best_len) {
            best_len  = match_len;
            best_dist = pos - i;
        }
    }
    *out_dist = (best_len >= LZ_MIN_MATCH) ? (uint16_t)best_dist : 0;
    *out_len  = (best_len >= LZ_MIN_MATCH) ? (uint8_t)best_len   : 0;
}
```
